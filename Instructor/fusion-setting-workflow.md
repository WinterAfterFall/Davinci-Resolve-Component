# Fusion Setting Workflow: สร้างชุด node ใหม่แบบไม่เสี่ยงให้ Resolve ค้าง

ขั้นตอนมาตรฐานสำหรับเพิ่มหรือแทนชุด node ในคอมพ์ Fusion ของ DaVinci Resolve ผ่าน AI + MCP
ใช้กับงานไหนก็ได้ เช่น กล่องข้อความ กราฟ หรือ transition
ที่มา: 2026-10-01 แก้คอมพ์ใหญ่ (~475 node) ผ่านสคริปต์โดยตรง แล้ว Resolve ค้าง 2 ครั้ง เสียทั้งงานและ token

## หลักการ

**ไม่แก้คอมพ์ใหญ่ทีละ node ผ่านสคริปต์** ให้เขียนชุด node ใหม่ทั้งชุดเป็นไฟล์ `.setting` (ข้อความล้วน)
ผู้ใช้วางเข้าไปเอง ทดสอบ แล้วค่อยลบชุดเก่า

- ระหว่างเขียนไฟล์ไม่แตะ Resolve เลย จึงไม่มีทางค้าง
- ถ้าผิดพลาดก็แค่ลบ node ที่วางเข้ามาทิ้ง คอมพ์หลักไม่เสียหาย
- ไม่ต้อง list หรืออ่านคอมพ์ใหญ่ไปมาหลายรอบ ประหยัด token
- ได้ไฟล์ที่เอาไปใช้ซ้ำในคอมพ์อื่นได้

## ขั้นตอน

### 1. เก็บข้อมูลจากคอมพ์เดิม (อ่านอย่างเดียว ให้น้อยที่สุด)
- อ่านค่าเฉพาะ node ที่เกี่ยวข้องโดยระบุชื่อ **อย่า list tool ทั้งคอมพ์**
- ถ้าต้องดูโครงสร้างทั้งชุด ให้ใช้ `timeline_item_fusion export_comp` ออกเป็นไฟล์ แล้ว grep เฉพาะ block ที่ต้องการ
- จดไว้ว่าชุดเก่ารับภาพเข้ามาจาก node ไหน และส่งออกไปที่ไหน จะใช้ตอนต่อสาย

### 2. เขียนไฟล์ `.setting` เป็น **Group** (`GroupOperator`)
- ใช้ Group ไม่ใช้ Macro เพราะผู้ใช้คลิกขวา → Ungroup (extract) แยกเป็น node ธรรมดาได้ ส่วน Macro ทำไม่ได้
- ตั้งชื่อ node ภายในให้มี prefix เดียวกัน (เช่น `NB_`) จะได้ไม่ชนกับชื่อในคอมพ์
- เปิดให้ปรับค่าบน Group ด้วย `InstanceInput` เช่น ข้อความ ขนาด หรือ Switch
- ช่องรับภาพของ Group คือ `MainInput1`, `MainInput2`, … และช่องส่งออกคือ `MainOutput1`
- ตัวแปรที่สร้างเองให้ใส่ใน `UserControls` ของ node ภายใน แล้วอ้างด้วย `NodeName.Control` ใน expression
- เก็บไฟล์ไว้ที่ `E:\Youtube\Workspace\WAF\DavinciResolveComponent\component\` (repo `DavinciResolveComponent`) ไม่ต้องเก็บใน repo MCP แล้ว copy ไปโฟลเดอร์ Fusion Macros ด้วย

### 3. ตรวจ expression ก่อนส่ง (สำคัญที่สุด)
- **ห้ามมีการอ้างกันเป็นวงกลม:** ถ้า node A ใช้ค่าของ B ใน expression แล้ว B ต้องไม่ได้รับภาพ (ทางตรงหรือทางอ้อม) มาจาก A
  ครั้งที่ค้างเกิดจากข้อความอ้าง `ImgBottom` ที่คำนวณจาก `Background.Height` ของ merge ซึ่งมีข้อความนั้นอยู่ข้างใน ทำให้เกิด deadlock
- ถ้าต้องใช้ขนาดภาพ (`Foreground.Width`, `Background.Height`) ให้คำนวณใน node ที่รับภาพจากต้นทางที่แยกออกมาเท่านั้น
  เช่น แผ่นใสกับรูปที่เสียบเข้ามา แล้วให้ node อื่นอ้างค่าที่คำนวณได้จาก node นั้นทางเดียว
- ค่าที่เป็นพารามิเตอร์ล้วน (เช่น `Mask.Width`, `Text.Size`) อ้างได้อย่างปลอดภัย

### 4. ตรวจไฟล์บนเครื่อง
- วงเล็บ `{` และ `}` ต้องมีจำนวนเท่ากัน
- `SourceOp` ทุกตัวต้องชี้ไปที่ node ที่มีอยู่ในไฟล์จริง
```bash
f=file.setting; echo "{ $(tr -cd '{' < $f | wc -c) } $(tr -cd '}' < $f | wc -c)"; grep -o 'SourceOp = "[^"]*"' $f | sort -u
```

### 5. ส่งให้ผู้ใช้วาง (เลือกทางใดทางหนึ่ง)
- **Clipboard (เร็วที่สุด):** `Get-Content file.setting -Raw | Set-Clipboard` แล้วให้ผู้ใช้คลิกพื้นที่ Nodes และกด Ctrl+V
- **Macros folder:** copy ไปที่ `%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\Fusion\Macros\`
  Resolve อ่านโฟลเดอร์นี้ตอนเปิดโปรแกรมเท่านั้น ต้องเปิดใหม่ก่อนจึงจะค้นเจอใน Select Tool (Shift+Space)
- ถ้าวางไฟล์ไว้ที่อื่น ช่อง Select Tool จะค้นไม่เจอ

### 6. ให้ผู้ใช้ต่อสายและทดสอบ **โดยยังไม่ลบของเดิม**
- บอกชัดๆ ว่าช่องไหนต่อจาก node ไหน เช่น Background ← node ที่ชุดเก่ารับภาพอยู่, Output → ช่องที่ชุดเก่าส่งไป
- ทดสอบก่อนด้วยการต่อเฉพาะช่องเข้า แล้วดูใน viewer (กด 1 หรือ 2) ยังไม่ต้องต่อ Output
- AI ตรวจผลด้วยการอ่านค่าหรือ expression ผ่าน MCP เท่านั้น **ห้ามสั่งเรนเดอร์** ถ้าต้องดูภาพให้ผู้ใช้ดูเอง

### 7. ลบชุดเก่า (หลังทดสอบผ่านแล้วเท่านั้น)
- ก่อนลบ เช็คผ่าน MCP ว่าไม่มี node อื่นนอกชุดอ้างถึง node ที่จะลบ ทั้งทางสายและทาง expression
- **ผู้ใช้เป็นคนลบเอง** (auto mode บล็อกไม่ให้ AI ลบ node ทั้งทางสคริปต์และคลิกหน้าจอ) ส่งรายชื่อ node ที่ต้องลบให้ชัดเจน
  แนะนำให้ **คลิกขวาที่ node → Delete** เพราะกดปุ่ม Delete มักไม่ติดถ้าพื้นที่ Nodes ไม่ได้ถูกเลือกอยู่ แล้วเช็คด้วย `FindTool` ว่าหายจริง
- ก่อนลบ ให้ย้าย expression ที่อ้าง node เก่า (สแกนทุก tool) ไปอ้าง node ใหม่ และต่อ output ใหม่ให้เรียบร้อย
- ให้ผู้ใช้กด Ctrl+S ก่อนลบ (หรือ AI สั่ง `project_manager save`)
- ลบแล้วอ่านค่ากลับมาเช็คว่าไม่มี expression ไหนเสีย

### 8. เปลี่ยนชื่อ จัดวาง และอัปเดตเอกสาร
- เปลี่ยนชื่อ node ภายในให้ตรงกับสไตล์ของผู้ใช้ (เช่น `NB_Title` → `NoteTitle`) Fusion แก้ชื่อใน expression ตามให้เอง
  ตัวที่ชื่อชนกับ node เก่า ให้เปลี่ยนหลังผู้ใช้ลบของเก่าแล้ว
- จัดวางด้วย `FlowView:SetPos` (ย้ายตำแหน่งอย่างเดียว ปลอดภัย): merge เรียงเป็นแกนแนวตั้ง แต่ละส่วนเข้ามาจากทางซ้ายของแถวตัวเอง
- อัปเดต `<Name>.md` ให้ตรงกับของจริง: ชื่อ node, control ที่ต้องปรับอยู่ที่ node ไหน, อะไรห้ามแตะ และ expression นอกบล็อกที่พึ่งพามัน

## กฎความปลอดภัยเมื่อต้องใช้สคริปต์กับคอมพ์จริง

1. **ห้ามดึงภาพหรือเรนเดอร์จากสคริปต์** (`tool.Output[time]`, `:Render()`) เพราะเป็นการเรนเดอร์บนเธรดของ UI แบบรอผล และเคยทำให้ Resolve ค้าง
   รวมถึง **`GetInput()` ของ input ที่ expression อ่านขนาดภาพ** (`Foreground.Width`, `Background.Height` ฯลฯ) ถ้ามีภาพต่ออยู่ การอ่านค่านั้นคือการสั่งเรนเดอร์ (ค้างครั้งที่ 3 ตอนตรวจ V_BarGraph) ให้อ่าน expression ด้วย `GetExpression` แทน
2. **`comp.Execute(lua)` ที่เรียกจาก Python ทำงานแบบไม่รอผล** ให้อ่านผลใน `run_inline` ครั้งถัดไป
   ถ้าอยากรู้ error ให้ครอบด้วย `pcall` แล้ว `comp:SetData("dbg", ...)` จากนั้นอ่านด้วย `comp.GetData("dbg")`
3. **ต่อสายด้วย Lua** (`tool.Input = other.Output`) ไม่ assign ผ่าน Python เพราะเคยต่อผิดตัว แล้วอ่านทุกสายกลับมาเช็ค
4. **เช็คชื่อก่อน rename** ถ้าชื่อซ้ำ Fusion จะเติม `1` ต่อท้ายเงียบๆ
5. **เช็ค `GetCurrentComp()` ก่อนแก้ทุกครั้ง** ผู้ใช้อาจสลับคอมพ์หรือเปลี่ยนชื่อ node ไปแล้วระหว่างนั้น
6. **เซฟก่อนแก้หลายขั้นตอน** และแนะนำให้เปิด Project Backups (Preferences → User → Project Save and Load)
7. **ถ้า Resolve ค้าง** และ CPU นิ่ง แปลว่า deadlock รอไปก็ไม่ฟื้น ต้อง End task
   เปิดใหม่แล้วเข้าหน้า Edit ก่อน เพื่อตรวจคอมพ์ผ่านสคริปต์ว่าไม่มี expression ที่ทำให้ค้างเหลืออยู่

## หมายเหตุ MCP
- `fusion_comp` ไม่มีคำสั่งเพิ่ม user control ให้ใช้ `script_plugin` → `run_inline` (Python) → `comp.Execute` (Lua) โดยตั้ง `t.UserControls = {...}; t:Refresh()`
- `bulk_set_expressions` ต้องระบุ `timeline_item_id` ด้วย
- ผู้ใช้ต้องการให้ใช้ MCP ก่อน การควบคุมหน้าจอใช้เป็นทางเลือกสุดท้าย
